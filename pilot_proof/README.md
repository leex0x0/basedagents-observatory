# pilot_proof — real end-to-end run on live data

This folder proves the kit works on **real** samples, not synthetic ones.

## What this is (honest labels)

- `samples-sandbox-proof.jsonl` — **28 real observations** collected by
  `probe.py` against the live confirmed endpoints, at a **5-minute interval**
  for **~30 minutes** (7 cycles × 4 endpoints) on **2026-10-26**, from a single
  Linux host in the build sandbox. Vantage label: `sandbox-proof`. One honest
  vantage, one machine.
- `report.json` / `report.md` — generated by `analyzer.py` over exactly those
  samples. Regenerate anytime with:
  ```bash
  python3 analyzer.py pilot_proof/samples-sandbox-proof.jsonl \
      --json-out pilot_proof/report.json --md-out pilot_proof/report.md
  ```

### Result of this mini-pilot
Window 2026-10-26T18:53:33Z → 19:24:10Z. 28 requests, **0 collection gaps**,
all four endpoints **100% available**, no incidents. p50 latency ≈ 1.1–1.6 s,
p95 ≈ 1.2–1.7 s. (Latencies are sandbox→Cloudflare→origin; a geographically
closer vantage will be faster.)

## What is still collecting (the full 48h / 2-vantage pilot)

The task's headline pilot is **48 continuous hours at 5-minute interval from ≥2
vantages**. That part runs via the two committed GitHub Actions workflows:

- `.github/workflows/pilot-ci-ubuntu-a.yml` → vantage `ci-ubuntu-a`
- `.github/workflows/pilot-ci-ubuntu-b.yml` → vantage `ci-ubuntu-b`

Both are GitHub-hosted `ubuntu-latest` runners (not machines I own — honestly
CI runners), scheduled independently (A on `*/5`, B offset by 2 min). Once this
repo is pushed and Actions is enabled, they probe every 5 minutes and commit
their samples into `samples/samples-ci-ubuntu-a.jsonl` and
`samples/samples-ci-ubuntu-b.jsonl`. After ~48 hours, run:
```bash
python3 analyzer.py --samples-dir samples --json-out report.json --md-out report.md
```
to produce the full 2-vantage report (with vantage-agreement on any incidents).

**Status at delivery:** the mini-pilot above is **done and real**. The 48h
2-vantage dataset is **still collecting** via Actions and will be complete ~2
days after push. Scheduled-run delays/drops on GitHub appear as **collection
gaps** in the data, never as target downtime.
